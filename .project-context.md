# StatSkill AI - Project Context & Handover

## 📌 Project Overview
**Target:** Smart India Hackathon (SIH) 2026 
**Problem Statement:** Capacity Building Commission (CBC) - AI Software Innovations for the Official Statistical System (MoSPI).
**Goal:** Build an intelligent competency-gap analysis engine with personalized recommendations, automated question generation from PDFs, and offline-capable edge caching for rural field offices.

---

## 🛠️ Tech Stack & Architecture
*   **Frontend:** React (Vite), Tailwind CSS (Mobile-first, responsive, accessible).
*   **Backend:** Node.js, Express, `pdf-parse`, `multer`.
*   **AI Engine:** Groq API (OpenAI-compatible) using `qwen/qwen3.8-27b` for lightning-fast MCQ generation.
*   **Database:** Persistent JSON File-System (`question_bank.json`) acting as an Edge SQLite mock for offline caching.

**Architectural Decision Record (ADR): Why Vite + Express instead of Next.js?**
We explicitly avoided Next.js. Government field offices often have terrible network connections. A decoupled Vite SPA downloads entirely to the browser once, allowing our offline fallback logic to work seamlessly. Additionally, processing heavy PDFs and waiting for AI queues requires long timeouts that would crash Next.js serverless functions (which typically timeout after 10s).

## ✅ What Has Been Done (Current State)

1.  **Sovereign Edge-AI Quiz Generation (Live RAG):**
    *   Backend endpoint accepts PDF uploads, extracts text buffer using `pdf-parse`, and hits the Groq API to generate valid JSON active-recall MCQs.
2.  **Hardware & Network Auto-Detection:**
    *   `detectPerformance.ts` silently runs on load. It checks CPU cores, RAM, and the `navigator.connection` API. If it detects a 2G/3G network or low RAM, it intercepts the app and drops it into `POTATO_DEVICE` mode (Offline Edge Cache).
3.  **Local Database Caching (The Hackathon Flex):**
    *   `QuizGenerator.ts` intercepts requests. If a PDF is uploaded, it checks `backend/src/data/question_bank.json`. If questions for that module already exist, it instantly serves them from the local cache (0ms latency, offline capable). If not, it hits Groq, generates them, and appends them to the JSON database permanently.
4.  **Dynamic Analytics Dashboard:**
    *   Wired directly into React State. It dynamically calculates the `assessmentsTaken`, `avgFracLevel`, and the `topGapSkill` based on live user input.
5.  **Frontend UI Engineering:**
    *   Mobile-responsive header, accessible `<button>` tabs, glassmorphism UI elements, and interactive empty states.
